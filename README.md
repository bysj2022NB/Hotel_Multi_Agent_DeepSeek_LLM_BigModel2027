# 基于 Python + LangGraph 多 Agent 协作的智能酒店预订系统 

## 项目概述

本项目是一套面向单家酒店的智能在线预订与客服系统，以“悦栖酒店”为业务场景，采用 Vue 3 + Flask 前后端分离架构，在 Windows 本地运行。系统将客房查询、在线预订、支付宝沙箱支付、订单履约、取消退款和客服工单连接起来，同时通过“小悦助手”提供自然语言咨询与业务办理入口。

用户端面向酒店宾客，提供注册登录、首页大厅、臻选客房、房型详情、入住指南、我的订单、我的收藏、服务工单、个人中心和 AI 智能预订助手。管理端面向酒店运营人员，提供运营看板、用户管理、房型与实体房间管理、逐日价格库存、订单与入住、支付退款、酒店政策、常见问题、服务工单、评价管理、收藏记录、客服会话、操作日志及酒店设置。

房型、价格、库存、订单、FAQ 和政策均来自数据库。对话侧使用真实的 LangGraph 状态图组织 Router、Knowledge、Tool、Escalation、Summary 五个 Agent，按照用户需求选择处理分支，完成知识检索、业务查询、操作提案与回复生成。预订、取消订单和提交工单需要用户点击确认卡后才能执行，AI 不直接替用户付款。

页面采用新粗野主义（Neubrutalism）风格：奶油白背景、日光黄主色、炭黑粗描边与硬阴影，辅以薄荷绿、珊瑚橙和酒店主题插图。用户端兼顾桌面与移动端；管理端强调表格可读性、状态辨识和操作反馈。

### 核心创新点

1. **多 Agent 协作编排**：Router 识别并拆分需求，路由到 Knowledge、Tool 或 Escalation 分支，再由 Summary 汇总答复。各 Agent 按需执行，并非每轮对话都调用全部节点。
2. **实时业务查询**：房态、价格和本人订单由 Tool Agent 调用后端业务服务获取；FAQ 和政策从管理员维护的知识内容中检索，减少脱离当前业务数据的回答。
3. **流式回复与处理过程可视化**：SSE 推送进度、文本增量、知识来源和业务卡片。每条助手回复上方可折叠查看实际 Agent 步骤、时间与操作摘要；展示公开处理记录，不展示模型内部推理或原始敏感日志。
4. **会话与操作持久化**：支持多会话、新建、重命名、删除、历史切换与多轮上下文。消息、业务卡片及公开处理事件保存到 SQLite，刷新后可恢复已有会话和保留期内的处理记录。
5. **用户确认后办理业务**：按房型名称匹配预订对象，自动读取当前账户的联系人资料；房型存在歧义时提供选择，缺少手机号时引导完善资料。确认执行前重新校验权限、报价、库存与订单状态。
6. **人工工单处理闭环**：Escalation Agent 整理咨询或投诉草稿，经用户确认后入库。管理员可回复、跟进和解决，宾客可以追加信息；新工单与新回复通过未读标记提示。
7. **运营控制台可视化**：围绕订单、收付款、入住率、房型销售和工单状态展示指标与趋势，辅助运营人员掌握酒店业务情况。
8. **权限隔离与交易留痕**：JWT 鉴权结合角色与资源归属校验，普通用户只能访问本人私有数据。订单、支付、退款采用受控状态流转、幂等处理与操作审计。
9. **异步结果自动同步**：订单、退款和工单等页面在可见时定期获取最新状态，操作完成后更新相关界面。页面切回前台时主动同步，减少用户手动刷新。

### 应用场景

- **酒店客服值班**：解答入住时间、行李寄存、优惠与退订问题，查询本人订单，并根据日期和人数查询可订房型。
- **自然语言预订**：宾客说明房型名称、入住日期、退房日期和人数，小悦生成报价与确认卡，减少在多个页面之间反复填写信息。
- **售后投诉处理**：需要人工跟进的问题转为服务工单；超过免费取消期限的退款申请由管理员结合关联工单审核。
- **房间运营配合**：维护房型图片、实体房号、逐日价格、销售配额和维护区间，使前台销售与后台履约使用同一套数据。
- **知识运营**：管理员手动维护 FAQ、入住须知、优惠说明及退订政策，通过关键词检索为客服回答提供依据。

## 技术架构

### 整体架构设计

系统采用前后端分离，分为前端展示层、后端业务层、Agent 协作层和数据与文件存储层，并通过独立 Worker 处理非即时完成的业务任务。

```text
Vue 3 客户端（5137）
├─ 宾客页面：查房 / 预订 / 订单 / 收藏 / 工单 / 个人中心
├─ 小悦助手：Fetch + SSE / Markdown / 业务确认卡 / 处理记录
└─ 管理页面：资源维护 / 订单履约 / 运营看板 / 未读提醒
          │ HTTP / JSON、SSE
          ▼
Flask + Waitress API（5020，统一前缀 /api/v1）
├─ 认证与权限 → 路由 → 酒店、预订、支付、工单等业务服务
├─ LangGraph：Router → Knowledge / Tool / Escalation → Summary
├─ 模型适配：HTTPX → OpenAI-compatible 模型服务
└─ 支付适配：支付宝官方 Python SDK → 支付宝沙箱
          │
          ▼
本地持久化与后台任务
├─ SQLite：账户、房型、库存、订单、支付、退款、知识、工单与会话
├─ SQLite 检查点：LangGraph 运行状态
├─ runtime：上传图片、日志、缓存、备份与验收报告
└─ Worker：过期订单处理、支付退款核验、日历补齐与过期记录清理
```

正式代码位于 `项目代码/backend` 和 `项目代码/client`；原 HTML/CSS/JavaScript 原型保留在 `项目代码/client/prototype`。业务数据库、会话检查点、上传文件、日志和备份统一写入项目根目录下的 `runtime`，不依赖启动命令所在目录。`runtime/models` 仅作为模型运行文件预留位置，当前系统不进行模型训练。

用户端入口为 `http://127.0.0.1:5137/`，管理端入口为 `http://127.0.0.1:5137/#/admin/login`。初始化、启动、迁移及备份恢复使用后端 `scripts` 目录中的脚本，具体操作见[运行说明](./运行说明.md)。

### 技术栈详解

#### 前端技术栈

- **核心框架**：Vue 3 + Composition API + TypeScript。
- **UI 组件库**：Element Plus，结合自定义新粗野主义样式与响应式布局。
- **状态管理**：Pinia，管理登录状态与用户资料。
- **路由管理**：Vue Router，使用 Hash 路由与页面访问守卫。
- **HTTP 客户端**：Axios，统一处理鉴权、令牌刷新和错误响应。
- **实时交互**：Fetch 接收 SSE 流式回复；业务页面通过可见性控制的轮询自动同步，默认约每 4 秒检查一次，避免请求重叠和旧页面响应覆盖新页面。
- **图表可视化**：ECharts 展示近 7 日收款趋势，指标卡和分布列表展示其他运营统计。
- **Markdown**：markdown-it 渲染助手回答，禁用原始 HTML，并统一段落、列表和表格间距。
- **构建与测试**：Vite、vue-tsc、Vitest；依赖版本以 `package-lock.json` 为准。

#### 后端技术栈

- **核心框架**：Python 3.13、Flask 3.1，使用 Waitress 提供本地 HTTP 服务。
- **数据库**：SQLite 3，采用 DELETE 日志模式；SQLAlchemy / Flask-SQLAlchemy 管理模型与事务，Flask-Migrate / Alembic 管理增量迁移。
- **身份认证**：JWT、密码哈希、刷新令牌与服务端会话校验；后端执行角色和数据归属检查。
- **Agent 编排**：LangGraph `StateGraph` 实际组织五个 Agent，配合 SQLite 检查点保存运行状态。
- **大模型接入**：通过 HTTPX 调用配置的 OpenAI-compatible API，Pydantic 校验结构化意图；支持流式文本、超时和异常处理。模型地址、密钥和名称由本机环境配置提供。
- **知识检索**：jieba 分词、同义词归一化和关键词加权匹配，检索已启用 FAQ 与当前有效政策；不使用文档上传解析、向量检索或模型训练。
- **支付集成**：支付宝官方 Python SDK，实现沙箱电脑网站支付、通知验签、主动查单、关单和全额退款。
- **文件服务**：Pillow 校验上传图片，使用随机对象名保存到 `runtime/uploads/rooms`，通过受控图片接口访问。
- **任务、审计与测试**：独立 Worker、任务租约、业务审计、日志轮转、SQLite 备份恢复和 pytest 回归测试。完整依赖以 `requirements*.txt` 为准。

## 核心功能模块

### 1. 用户管理系统

#### 功能特性

- 支持用户注册、登录、退出和 JWT 鉴权，管理员使用独立登录入口。
- 个人中心维护昵称、联系电话和密码；AI 预订从当前账户资料读取联系人信息。
- 管理员可分页查询用户、启用或停用账号、重置密码，相关管理操作留有审计记录。
- 普通用户仅可访问本人的订单、收藏、工单和会话；管理员通过受保护的管理接口处理酒店业务。
- 顶部导航居中展示，头像菜单支持进入个人中心及退出；详情页提供明确的站内返回入口。

### 2. 智能客服模块

#### 功能特性

- 支持多会话列表、新建、重命名、删除和历史恢复，通过上下文理解连续补充的日期、人数及房型选择。
- 小悦助手采用单屏工作区：移除独立大标题和页面底部信息区，导航、会话列表、对话区及输入框在一屏内布局，历史消息在对话区内部滚动。
- SSE 流式展示回复文本、处理状态、知识来源及业务卡片；“处理过程”折叠框展示实际 Agent 协作步骤与公开执行记录。
- Router 识别意图；Knowledge 检索酒店知识；Tool 查询房态、价格、本人订单并整理业务提案；Escalation 整理工单；Summary 根据结果生成中文回复。
- 支持按房型名称匹配预订对象，无需宾客手动提供房型编号。名称不能唯一确定时显示房型选择卡；缺少必要日期或人数时只补问缺失信息。
- 预订默认使用账户昵称与手机号，资料不完整时提供个人中心入口；确认卡显示房型、日期、人数、费用、联系人与政策，供用户核对。
- 创建订单、取消预订和提交工单均需点击具体确认卡；重复确认按幂等规则处理，价格、库存或状态变化时重新校验并提示。
- 房型、订单和工单结果卡可跳转业务详情。模型不可用时明确提示，普通查房、订单和工单页面仍可使用。

### 3. 房间与订单管理

#### 功能特性

- **房型浏览**：臻选客房按日期、入住人数、床型、设施和预算筛选，并支持价格排序。当前初始化 10 个房型，各有不同封面图片，详情展示面积、设施、政策和评价。
- **收藏与评价**：收藏按钮即时切换状态；房型评分统计全部公开评价，包括已初始化的评价内容，隐藏评价不计入。用户新提交评价仍要求本人订单已完成，每笔订单限一条。
- **资源管理**：区分房型、实体房间和逐日库存。管理员维护房型资料、图片、房号、房间启停、维护区间、日历价格和销售配额；历史业务记录保留。
- **报价与预订**：每单一个房型的一间房，可连续入住多晚；退房日不占用当晚库存。后端计算逐晚金额，在事务中校验库存并创建订单，避免最后一间房被重复预订。
- **订单快照**：保存下单时的房型信息、逐晚价格和退订政策；默认报价有效 5 分钟，待支付订单保留库存 15 分钟，超时按交易核验结果处理。
- **支付与退款**：通过支付宝沙箱付款，后端验证支付结果后确认订单，不以浏览器跳转认定支付成功。支持主动查单、关闭未支付交易、全额退款及失败重试。
- **取消规则**：默认在入住前至少 24 小时可以免费取消；超过期限通过退款申请工单人工审核。退款成功后才释放对应库存，政策修改不追溯既有订单。
- **入住与退房**：管理员为已确认且处于入住日期范围内的订单分配同房型、连续可用的实体房间。提前入住原因可留空，填写时最多 200 字；办理退房后订单完成。
- **订单详情**：突出订单、支付和退款状态，展示入住日期、联系人、房号、费用明细与取消截止时间。订单列表、详情及管理端相关页面自动同步后台处理结果，无需依赖手动刷新。
- **受控业务流转**：订单依次经历待支付、待入住、已入住、已完成，或进入取消退款流程；支付、退款和订单不能通过任意增删改查绕过业务规则。

### 4. 知识库与工单

#### 功能特性

- 管理员手动录入、编辑、分类和启停 FAQ，维护入住须知、退订政策、优惠政策与检索关键词；发布政策时保留版本记录。
- 入住指南面向宾客展示政策和常见问题，支持关键词搜索与问题展开；影响报价和退款资格的规则由业务服务执行。
- 工单支持咨询、投诉、退款申请和其他类别，可关联本人订单；用户可以直接提交，也可以由助手整理草稿后确认提交。
- 管理员查看工单详情、回复并调整处理状态；宾客可以继续补充信息。已关闭工单不再接受回复，需要时新建关联工单。
- 管理端“服务工单”导航旁显示有未读内容的工单数量，列表中标记“新消息”。查看具体工单后清除该管理员的对应提示，宾客再次回复时重新标记；未读记录持久化并按管理员独立保存。
- 工单列表和打开的详情可自动同步；后台回复后，宾客端能获取最新回复与处理状态。
- 例外全额退款通过关联退款申请工单审核；审批弹窗提供可选工单下拉框，后端再次核对订单、宾客与工单状态。

### 5. 管理控制台

#### 功能特性

- **运营指标**：今日订单、今日净收款、今日入住率、待处理工单，以及实体房间、启用房型、有效宾客和客服会话数量。
- **趋势与分布**：近 7 日收款趋势、所选区间订单状态分布、房型销售分布和工单状态分布，页面注明统计口径。
- **业务工作台**：集中处理用户、房型、房间、库存、订单、支付退款、政策、FAQ、工单、评价、收藏、会话和酒店资料。
- **可读业务信息**：订单、工单、支付退款和收藏等列表展示宾客名称、房型名称及相关业务编号，减少仅凭编号识别记录的负担。
- **自动更新与消息提示**：订单、支付退款、工单和运营看板定期同步；后台处理完成后更新状态，服务工单导航持续显示未读提醒，编辑中的表单不被后台同步覆盖。
- **运行与审计**：提供配置状态和后台任务状态查看，维护价格调整、政策发布、订单履约、退款批准及工单处理等操作记录；运行文件统一归入 `runtime`，支持迁移和备份恢复。

当前系统定位为 Windows 本地运行的单酒店项目，支付使用支付宝沙箱，模型通过配置的接口接入；不包含多酒店入驻、真实资金支付、部分退款、会员积分、第三方 OTA 对接或模型训练。上述说明依据截至 2026-09-17 的当前实现整理，详细业务规则与操作方法可结合[系统文档](./系统文档.md)和[运行说明](./运行说明.md)阅读。
